# Personal OS 第二阶段规划：目标、任务与基于事实的问答

状态：用户已确认 P2-A 方案，扩展接口已冻结，实施与验证进行中。日期：2026-11-26（Asia/Shanghai）。

本方案已由用户通过“按此方案开始实现”确认。扩展规则以[冻结契约](../packages/contracts/PHASE-2-GOALS-TASKS.md)为准；本文描述范围与验收标准，不代表测试、生产发布或真机验收已完成。桌面与 P2-B 不在本次实现范围内。

## 1. 总目标与本阶段成果

Personal OS 的长期目标是：云端持续管理会话、目标、任务、计划、记忆、审批和调度；iPhone 作为日常入口；桌面后续提供本机文件、终端和应用执行能力。电脑离线不影响云端核心能力。

本阶段先交付一个可日常使用的数据闭环：

> 手机上创建目标和任务 → 更新真实进度 → 云端持久保存 → 关联该目标提问 → AI 根据同一次读取的任务记录回答，并能查看依据。

本阶段任务是业务记录，聊天 Run 是一次模型生成。创建任务不会自动调用模型、运行脚本或派给电脑，聊天生成完成也不会自动把业务任务标为完成。

## 3. 本次最小交付范围（P2-A）

### 3.1 目标

- 新建、查看列表与详情、修改标题/说明/成功标准/目标日期。
- 状态：进行中、已完成、已归档。归档保留历史，支持恢复。
- 目标下有一层任务，不引入项目/目标/子目标三套重叠对象。
- 同时展示完成项数、受阻项和最近更新时间。
- 目标完成由用户明确操作；任务全完成只提示可以完成目标。
- 存在未完成且未取消的任务时，不能直接完成目标；须先处理这些任务。
- 已完成、已归档目标只读；需要继续工作时先恢复。空目标允许用户根据成功标准主动完成。

### 3.2 任务

- 新建、编辑标题/说明/可选截止日，更新状态和进展备注，取消或重新打开。
- 一项任务只属于一个目标；首版没有跨目标移动、嵌套子任务和独立任务收件箱。
- 状态为：待做、进行中、受阻、已完成、已取消。
- 任务为用户管理的工作记录；首版不设置会触发执行的 AI 负责人。
- 受阻时须填写原因；恢复为进行中时保留旧原因到历史。
- 完成时可填写结果说明；用户自行确认完成，AI 不根据聊天内容改状态。
- 保留每次状态变化和备注的时间记录；修改任务正文与追加进展分开表达。
- 本轮不提供永久删除，误建内容可取消或归档，并可恢复。

### 3.3 目标关联问答

- 从目标详情点击“和助手聊这个目标”，进入现有聊天页；也可在发送前选择/清除目标关联。
- 关联按会话保存在本地界面状态，每条待发消息保存当时选择的目标 ID；恢复发送不能悄悄换成后来选中的目标。切换目标不删除原聊天历史，worker 必须以本条服务端快照判断当前状态，历史回复不得覆盖新事实。
- 未关联目标时保持普通聊天。关联目标时只读取该目标和其任务，普通聊天不自动打包所有个人数据。
- 一条问题对应一份服务端读取时间、目标/任务版本和上下文快照。回复旁提供“查看依据”，展示本次实际采用的记录，而不是点击时的最新值。
- 任务内容在生成期间更新时，本次回答仍基于原快照；再次提问读取新快照。
- 提供已完成/待做/进行中/受阻/取消的确定性统计、任务 ID 与标题、截止日、最近进展及更新时间。完整任务清单和长备注均有界限；超出时明确省略范围，不能把部分记录当全量。
- 没有记录、读取失败、数据已过期或用户没有关联目标时，明确表达边界。不能仅因回答语气流畅就显示“已核对全部任务”。
- 用户可让助手建议拆分任务；P2-A 输出建议文本，由用户在目标页创建。聊天生成结构化变更草案并确认保存属于后续 P2-B。

## 4. 手机交互方案

### 4.1 一级入口

底部改为“聊天 / 目标 / 我的”。任务放在目标详情中，不增加第四个任务标签；每日计划、记忆、审批页面等以后有真实能力再接入。

### 4.2 目标列表

- 导航栏“目标”，右上角新建。
- 顶部按“进行中 / 已完成 / 已归档”切换；默认进行中。
- 每个目标显示标题、完成项数/有效任务总数、受阻数、目标日期（如有）与最近更新时间。
- 空列表明确显示“还没有目标”，提供创建入口；不会预填示例目标。

### 4.3 目标详情

- 标题、说明、成功标准和可选目标日期。
- 任务统计与任务列表，默认先显示受阻、进行中、待做，完成项可折叠。
- 新建/编辑任务打开表单；状态和进展在任务详情操作，待服务器确认后才显示已保存。
- 底部主要操作“和助手聊这个目标”。
- 任务详情展示当前状态、截止日、进展记录与结果说明；失败保留用户输入供重试。

### 4.4 聊天

- 保留已验收的会话选择器与型号行。
- 新增可清除的目标关联条；显式关联后才携带业务数据。
- 目标问答回复展示资料时间和“查看依据”，正文表达下一步建议及受阻原因。
- 页面不展示数据库版本号、请求幂等键和内部错误栈。

### 4.5 同步状态

- 成功：已同步，附最后读取时间。
- 离线：可读已缓存的目标和任务，标明“离线 · 上次同步时间”。没有缓存时说明尚无离线数据。
- P2-A 不排队提交离线目标/任务变更；离线表单可保留身份隔离的草稿，联网后由用户再次保存。
- 保存中防重复点击；网络结果不确定时保留原操作 ID 并先查询/重试原操作，不生成第二份记录。
- 数据冲突提示“内容已更新”，展示服务端最新内容并保留本地草稿；不自动覆盖。

## 5. 数据与一致性规则（拟议）

### 5.1 对象

| 对象 | 拟议关键字段 | 说明 |
| --- | --- | --- |
| Goal | id、ownerId、title、description、successCriteria、targetDate、status、archivedFromStatus、revision、createdAt、updatedAt | ownerId 由服务端设置；日期是可选 YYYY-MM-DD；归档保存原状态 |
| Task | id、ownerId、goalId、title、description、dueDate、status、revision、createdAt、updatedAt | 不含脚本、设备执行、审批或模型运行字段 |
| ProgressEntry | id、taskId、actorDeviceId、kind、note、fromStatus、toStatus、createdAt | 追加记录；不由模型自由改写旧事实 |
| GoalView | goal、tasks、summary、viewRevision、asOf | 同一次数据库读事务取得，供详情和问答共用 |
| GoalQuestionContext | runId、goalId、viewRevision、asOf、summary、includedTasks、omissions | 在生成前持久化；用于同 run 恢复与查看依据 |
| MutationReceipt | client device、commandId、canonicalPayloadHash、首次结果 | 解决保存超时和重复提交 |

服务端实体时间使用 UTC ISO-8601，手机按本地时区显示；截止日与目标日期是自然日，不伪装成提醒时间。

### 5.2 状态与进度

- 任务：待做 → 进行中/受阻/已完成/已取消；进行中与受阻可按用户操作切换；已完成和已取消可重新打开为待做。
- 已完成/已取消内容如要继续推进，先重开，再更新状态；不做隐式复活。
- 目标：进行中 → 已完成或已归档；已完成可恢复进行中或归档；已归档恢复为归档前状态，恢复后若为已完成仍需再次重开才可编辑。
- 完成比例 = 已完成任务数 / 未取消任务总数。无有效任务时展示“暂无任务”或“无有效任务”，不显示 100%。
- 不设置人工百分比，不把 AI 生成次数计入业务任务进度，不自动完成目标。
- 取消任务从有效总数排除，但仍可在详情和依据中查到取消事实。

### 5.3 身份和权限

- 沿用当前单用户实例，已配对 client 属于同一账户，共享目标/任务；不宣称具备多用户隔离。
- `ownerId`、actor 和时间由服务端确定，客户端不能指定其他 owner。
- client 可以创建和修改目标/任务；agent 仅获得本阶段所需的业务资料读取权限，不能调用业务写接口。
- 目标详情、任务、上下文与问答依据均需认证；不存在对象返回明确 404，角色越权返回 403。
- 不复用 v1 设备 token，不迁旧插件库；新数据仅进入独立 v2 业务表。

### 5.4 并发、同步与幂等

- 所有业务写请求带 commandId；修改再带 expectedRevision。首次结果与状态变化同事务写入。
- 同设备、同 commandId、同操作与正文返回首次结果；同键不同正文返回 409，不再创建对象或进展记录。
- 先查幂等回执，再检查版本；已成功请求重放不会因当前 revision 变化变成失败。
- 更新/追加进展/状态变更推进任务 revision，并推进所属目标的 viewRevision；目标内容变化也推进该 viewRevision。
- 目标详情在单一读事务取得一致视图。首版按页读取目标列表，目标详情使用有上限的完整视图；具体数量/正文上限在契约冻结时写死并测试。建议每目标最多 100 项任务，达到时提示拆分目标。
- 列表读取、详情刷新和问答快照分别记录 asOf；切到前台、进入详情、保存成功及手动刷新时更新；前台目标页每 15 秒刷新，切后台停止。
- 切身份/服务器后隔离缓存、草稿和在途回写；保留现有聊天幂等键、会话游标、Keychain 和 RunRecord 行为。

## 6. API 与 worker 方案（提案，不是已冻结接口）

采用兼容新增，不改变现有聊天、领取、取消和完成端点的既有 wire 语义。先增加目标/任务扩展契约，再同步 OpenAPI 和 iOS 客户端实现。

| 能力 | 拟议入口 | 要点 |
| --- | --- | --- |
| 能力探测 | GET /v2/capabilities | 返回目标任务扩展版本；旧服务无此接口时只显示原聊天能力，网络错误不能伪装成无数据 |
| 目标列表/创建 | GET /v2/goals；POST /v2/goals | 分页/状态筛选；创建带 commandId |
| 目标一致视图 | GET /v2/goals/:id | 返回 GoalView，包含 summary 与 viewRevision |
| 目标修改和状态变化 | POST /v2/goals/:id/commands | commandId、expectedRevision、显式动作与字段 |
| 任务创建 | POST /v2/goals/:id/tasks | commandId；验证目标可编辑 |
| 任务详情/进展 | GET /v2/tasks/:id | 任务与分页进展记录 |
| 任务修改/记进展/状态变化 | POST /v2/tasks/:id/commands | 单一写入口；不并行保留多套 cancel/verdict 写语义 |
| 带目标资料提问 | POST /v2/goals/:id/questions | conversationId、clientRequestId、text；返回现有 message/run 回执形状 |
| 查看某次回答依据 | GET /v2/runs/:id/goal-context | 只返回该次实际快照，client/agent 认证读取 |

目标提问在一个事务中写入 user 消息、同一 run 与目标资料快照。按会话复用原 clientRequestId；同一目标提问重复返回首次 run/context，同键换正文/目标返回 409；与普通消息入口的键碰撞也不得产生额外消息。手机待发项须记录意图为普通聊天还是目标问答，不自动跨入口降级重发。

worker 在正常聊天读取之后查询此 run 的上下文；有资料则加入有界、带来源的结构化数据块，无资料的普通聊天保持旧逻辑。上下文是数据，不接受其中要求改系统规则或调用工具的文本。资料读取失败不得静默生成看似已核验的目标回答，返回可重试的明确失败。

上下文采用服务端确定性统计和受限明细，明细建议最多 30 项、每项最近 3 条进展，总上下文建议不超过 16,000 字符；省略项数和原因始终可见，目标总统计仍基于全量有效记录。最终上限须由一次定向 provider 兼容验证和完整任务样例确定，不能因截断产生错误的任务总数。

本阶段不引入模型工具调用或新的输出 JSON 解析链，复用现有 Responses 文本输出；业务记录通过服务端读取，并附确定性“查看依据”。API 与 worker 的能力启用须随匹配版本发布，不能只凭 health.model 判断支持或在线。

发布顺序为：先部署兼容新增接口的 API，保持目标问答入口未启用 → 暂停领取并等待/安全恢复旧在途 run，更新 worker → 验证新 worker 的资料读取能力 → 启用目标问答能力 → 最后交付新版手机。不能让旧 worker 领取带目标资料的 run。worker 回滚时先关闭新目标问答入口并妥善处理带资料的在途 run；不能回滚后把它们当普通聊天继续回答。

| A13 | 切服务器/身份时旧响应迟到 | 不污染当前目标、草稿或聊天 |
